## 2. Conventions

* Base URL `/api/v1`. JSON in/out unless noted. Errors: HTTP status + `{"detail": "message"}` (422 validation → `detail` list).
* Auth: `Authorization: Bearer <access_token>`. Roles: `citizen`, `officer`, `worker`, `supervisor`, `admin`.
* Datetimes: naive UTC ISO strings (no `Z`); the frontend `parseDate()` treats them as UTC.
* **Ticket id in URLs = public ticket number**, e.g. `CL-2026-00142` (format `CL-{year}-{id:05d}`, assigned right after insert). The JSON field is `ticket_number`.
* Paged lists: `{ "items": [...], "total": 123, "page": 1, "page_size": 25 }` (`page` 1-based, `page_size` ≤ 100).
* Users: `{id,email,display_name,role,department_code,corporation_code,phone,preferred_language,is_active,is_demo,created_at,last_login_at}`.
* Privacy: citizens never receive other citizens' names/emails/phones/exact coordinates. Citizen views of a complaint they do not own get coordinates rounded to 3 decimals and no reporter data. Internal notes (`visibility="internal"`) are never returned to citizens.

### Duplicate check (`services/duplicate_service.py`)
`POST /complaints/duplicate-check` (auth, rate limited) body:
`{description, language?, latitude, longitude, location_address?, location_accuracy_m?, location_source?, category_hint?, subcategory_hint?}` →
```json
{ "has_possible_duplicates": true,
  "matches": [ { "ticket_number":"CL-2026-00142","category":"roads","subcategory":"pothole","status":"in_progress",
                 "distance_m":42,"same_reporter":true,"created_at":"...","similarity":0.91,"summary":"...","locality":"Indiranagar",
                 "supporting_count":2,"i_follow":false,"latitude":12.976,"longitude":77.605 } ],
  "recommended_action": "follow_or_add_evidence | review | none",
  "settings": {"same_user_radius_m":150,"community_radius_m":100,"lookback_days":180} }
```
Rules (README "Duplicate detection"): same-user candidates within `SAME_USER_DUPLICATE_RADIUS_METRES` (150); other users' candidates within `COMMUNITY_DUPLICATE_RADIUS_METRES` (100); only complaints created within `DUPLICATE_LOOKBACK_DAYS` and not `rejected`; recently resolved ones are included (ranked lower, flagged by `status`). Spatial = bounding-box SQL prefilter + haversine in Python (portable to SQLite and PostgreSQL; **no PostGIS**). Never match by location alone: score = category match (use `category_hint` or a quick keyword guess) + text similarity (normalised token Jaccard / difflib, multilingual-safe) + proximity + same-reporter boost; drop candidates whose category conflicts with a known hint and whose text similarity is very low. Footprint-larger categories (drainage `flooding`, trees `fallen_tree`) use 2x radius. For other users' matches: **never** return reporter identity; coordinates rounded to 4 dp for non-owned. Persist `DuplicateCandidate` rows with `decision="shown"`.

### Behaviour (README section 5)
* Provider chain from `AI_PROVIDER_ORDER` (default `openai,ollama,rules`). **OpenAI** (Responses API via `openai` SDK, model `OPENAI_TRIAGE_MODEL`, JSON output validated with Pydantic, image inputs as base64 data URLs when photos are present, timeout `AI_TIMEOUT_SECONDS`) → on missing key/any error → **Ollama** (`POST {OLLAMA_BASE_URL}/api/chat`, `OLLAMA_MODEL`, `format:"json"`, `stream:false`; photos analysed only when `OLLAMA_VISION_MODEL` is set) → on failure → **deterministic rules** (multilingual keyword lists in English + Kannada/Hindi/Tamil/Telugu/Malayalam transliterations/native words for each category/subcategory; must work offline). `TriageResult.provider` says which produced the classification and `notes` records fallbacks ("OpenAI unavailable → Ollama").
* The model only proposes `category`, `subcategory`, `summary`, `translated_description` (English, only when language != en), `image_observations`, `reason`, `confidence`, four 0–100 factors (`safety_risk, public_impact, issue_scale, location_sensitivity, duration`) and a danger flag. Taxonomy values are validated against the DB `categories` table; anything out-of-taxonomy is rejected → category `other`, review flagged. **No chain-of-thought is requested or stored.**
* Severity = deterministic: `score = 0.35*safety + 0.25*impact + 0.20*scale + 0.10*location + 0.10*duration` (weights from `app_settings.severity_weights`), thresholds 0–24 low, 25–49 medium, 50–74 high, 75–100 critical (from `app_settings.severity_thresholds`). Then apply **escalation rules**: credible immediate danger keywords/flag (live/exposed/fallen wire, sparking, open manhole on road, large tree blocking road/on power line, flooding with electricity, gas smell…) → at least `high`, and `critical` when explicit danger to life; routing-rule `min_severity` floors apply. `reason` = ONE line ≤160 chars, e.g. "Deep pothole beside a bus stop — risk of falls/vehicle damage." Same text language rules: reason in English.
* `requires_human_review=true` when: confidence < 0.6, category `other`, image vs text conflict, danger flag, severity critical, routing rule requires review, provider `rules` with low keyword certainty. Provide `review_reasons`.
* Routing: `resolve_route` picks the most specific active `authority_routing_rules` row (subcategory match beats category-only; fall back to `categories.default_department_code`). Returns department, agency kind, review flag, note, severity floor. Water/sewer network → BWSSB; exposed wire/outage → BESCOM; streetlight fixture → electrical (corporation); stormwater/flooding → drainage; sewer overflow subcategory `sewage_overflow` → BWSSB. A photo that contradicts the text only adds a review flag (never claims the photo proves severity/location).
* Priority (README): `priority = severity_component(0–60: low 0, medium 20, high 40, critical 60) + ageing(0–15, +1 per ~6 h open, capped) + public_impact(0–15 from stored impact via `supporting_count` and category) + sla(0–10: grows as `sla_due_at` nears, 10 when overdue)`; rounded to 1 dp. Medium that is long overdue can outrank a fresh High without being relabelled.
* `sla_due_for`: lookup `sla_policies` (category-specific else `*`) → `start + target_hours`.
* `POST /voice/transcribe` (`api/v1/voice.py`, auth, rate limited 20/hour, multipart: `audio` file, `language?`, `duration_seconds?`): validate size (`MAX_AUDIO_SIZE_MB`), MIME/extension allow-list (webm, ogg, wav, mp3, m4a, mp4, mpeg), declared duration ≤ `MAX_AUDIO_DURATION_SECONDS`; call OpenAI audio transcription with `OPENAI_TRANSCRIPTION_MODEL` (language hint only when one of the six codes); **delete audio immediately after** (use in-memory bytes/temp file removed in `finally`); never log audio or transcript text. Returns `{transcript_id, text, detected_language|null, language_used, model}` and inserts a `VoiceTranscript` row (`original_transcript`). If no `OPENAI_API_KEY` → 503 `{"detail":"Voice transcription needs an OpenAI API key on the server. Please type your complaint instead."}`. Also `PATCH /voice/transcripts/{id}` `{confirmed_transcript}` (owner) to store the citizen-corrected text.
* `GET /ai/status` (staff) → `{providers:[{name,configured,reachable|null,model}],order,vision:{openai:bool,ollama:bool}}` (Ollama reachability = quick GET `/api/tags`, 2 s timeout). `POST /ai/preview-triage` (staff office) `{text,language?}` → TriageResult (for the admin console).
* Tests must not hit the network: the test env sets `AI_PROVIDER_ORDER=rules`; unit-test OpenAI/Ollama paths with `monkeypatch`/fake clients.

## 7. CleanRoute — owner: CLEANROUTE agent (`api/v1/garbage.py`, `services/garbage_service.py`, `seed_garbage.py`)

Everything here is **SIMULATED** in this prototype and must be labelled: every response includes `"simulated": true` and `"source_label": "DEMO / SIMULATED GPS"`.
* Seed (`seed_garbage.seed(db)`, idempotent): 4 fictional vehicles `CL-GT-01..04`, 4 routes with ≥6 waypoints each along real Bengaluru localities (Malleshwaram, Rajajinagar, Vijayanagar, Shivajinagar, Indiranagar, Whitefield, Koramangala, Jayanagar, Basavanagudi, JP Nagar — use plausible lat/lng inside Bengaluru; do NOT claim ward/corporation, leave `city_corporation_code` null and `ward_label` a plain demo label), 16 bins near the routes with initial fill levels and readings (`source="simulated"`), driver labels like "Worker 024 (fictional)".
* `garbage_service.py`: `async start_simulator()`, `async stop_simulator()`, `is_running()`, `snapshot(db)`; background `asyncio` task every `GARBAGE_SIMULATION_INTERVAL_SECONDS`: advance each vehicle along its route polyline (interpolate; speed 12–28 km/h simulated; progress %, next stop name, ETA), raise bin fill levels slowly with per-bin rate, when a vehicle passes within ~40 m of a bin that is ≥50 % create a `CollectionEvent` and reset the bin to a low value, write `VehicleLocation` (keep only the last N=200 per vehicle) and `BinReading` rows, and broadcast over the WebSocket. Pickup prediction = linear estimate from the last readings, returned as `predicted_full_at` labelled estimate. Bin states from `app_settings.bin_thresholds` (0–50 normal, 51–80 filling_up, 81–95 collection_recommended, 96–100 overflow_risk). Auto-alert: crossing 96 → in-memory alert list + (once per crossing) no complaint is created automatically.
* REST: `GET /garbage/vehicles` → `{simulated,source_label,updated_at,items:[{id,code,status,current_task,route:{id,code,name,schedule_window},latitude,longitude,speed_kmh,heading,route_progress_pct,next_stop,eta_minutes,recorded_at,is_simulated, driver_label(office+worker roles only)}]}`; `GET /garbage/vehicles/{id}`; `GET /garbage/routes` → `[{id,code,name,waypoints:[[lat,lng]…],schedule_window,ward_label,vehicle_codes}]`; `GET /garbage/bins` → `{simulated,source_label,thresholds,items:[{id,code,name,locality,latitude,longitude,fill_pct,state,source,recorded_at,predicted_full_at|null,route_id,is_simulated}]}`; `GET /garbage/summary` → `{vehicles_active,bins_total,bins_overflow_risk,bins_collection_recommended,collections_today,last_updated}`; `GET /garbage/alerts` (office roles) → `{overflow_risk:[bin…],missed_collection:[bin… with reason]}`; `POST /garbage/bins/{id}/reading` `{fill_pct 0–100, source:"worker"|"sensor"}` (worker/officer/supervisor/admin); `POST /garbage/collections` `{bin_id,vehicle_id?}` (same roles) → CollectionEvent + reset reading; `GET /garbage/collections?limit=` (office roles) history.

## 8. Recognition — owner: RECOGNITION agent (`api/v1/certificates.py`, `games.py`, `services/certificate_service.py`, `points_service.py`, `achievement_service.py`, `seed_recognition.py`)

* `certificate_service.issue_for_complaint(db, complaint, issued_by_user)` — **only** called by verify-resolution. Idempotent. Issues a `Certificate` to the complaint's primary reporter only if the complaint is `resolved` and `verified_by_user_id` is set (never for merely "worker clicked resolve"). `code` = 12-char uppercase url-safe random (unique). PDF via `reportlab` saved in `CERTIFICATE_STORAGE_DIR/<code>.pdf`: title **Certificate of Appreciation**, "CivicLens — Bengaluru, Karnataka pilot", citizen display name, contribution sentence ("…reported an issue that led to a verified improvement" — must NOT imply the citizen performed the repair), ticket number, issue date, certificate ID, QR code (`qrcode`) pointing to `{PUBLIC_BASE_URL}/verify/{code}`; calm civic-minimal look, no gradients; fixed English text plus the citizen name. Also awards points (`points_service.award`: `verified_first_report` 10, + `verified_resolution` 30 per settings; additional `verified_evidence` 10 per distinct verified supporter) and runs `achievement_service.evaluate(db, user_id)`, notifies the citizen ("certificate issued") via `notification_service`. Followers/supporters get points only for verified evidence contributions (not for following).
* `points_service`: `award(db,user_id,reason_code,points,ref_type,ref_id,note)` (append-only, de-duplicated by (user, reason, ref)), `total_points`, `level_for(verified_contributions)` using `app_settings.recognition_levels` (Civic Observer 1, Neighbourhood Helper 5, Community Guardian 15, Civic Champion 30, City Ambassador 50). Never award for merely submitting complaints. Daily game cap from settings (`daily_game_cap` 15 points/day across games).
* `achievement_service.evaluate(db, user_id)` → unlocks: First Voice (first verified voice-submitted report: complaint `submitted_via="voice"`), Water Guardian (verified `water` contribution), Night Owl (verified streetlight issue reported 19:00–05:00 IST), Clean Sweep (verified `waste` contribution), Neighbourhood Watch (verified supporting evidence), Civic Observer.. levels, Quiz Whiz (quiz score ≥80), Tidy Citizen (Clean City Challenge ≥80). `secret` ones are hidden in the catalogue until earned.
