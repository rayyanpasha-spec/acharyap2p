# City in Motion — contract addendum (read together with docs/API_CONTRACT.md)

Source feature spec: `docs/SPECIFICATION_3D_CITY_TWIN.md`. **Principle from the product owner: the 3D map is a visual layer on top of the existing CivicLens system, not a separate app. Every complaint, vehicle, route and bin on the map comes from the SAME FastAPI/SQL tables the rest of the product uses. The frontend never invents records.**

## Deviations from the 3D spec (deliberate, honest)
* URLs live under our versioned prefix: `/api/v1/city-twin/*` and WebSocket `/ws/v1/city-twin/live` (not `/api/city-twin`).
* Our verified-resolution status is named `resolved` (it can ONLY be reached via `verify-resolution`, so it equals the spec's `resolved_verified`). Do not add a new status.
* No PostGIS: coordinates are plain float columns (haversine/bbox in Python). Spatial storage differs from the spec; behaviour is the same.
* Basemap: OpenFreeMap `liberty` vector style (`https://tiles.openfreemap.org/styles/liberty`) — verified reachable without an API key; vector source `openmaptiles`, source-layer `building` (the style already has a `building-3d` fill-extrusion layer). Attribution must be visible: "OpenFreeMap © OpenMapTiles Data from OpenStreetMap". Style URL is configurable via `VITE_CITY_MAP_STYLE_URL` (default = the URL above).
* Truck model: no third-party model is downloaded. The truck is a **procedural low-poly Three.js model built in code** (cab, tank body, wheels, CivicLens-green/white). If `/models/vehicles/garbage-truck.glb` exists it is loaded instead (GLTFLoader) — document that in `docs/assets/ASSET_CREDITS.md` (no GLB is bundled; credit file explains the procedural model and the GLB hook).
* Libraries installed: `maplibre-gl@4.7.1` (custom layer API `render(gl, matrix)`), `three@0.169.0`. Do not install others.

## Backend (owner: CITY-TWIN-BE) — files: `backend/app/api/v1/city_twin.py`, `backend/app/services/city_twin_service.py`, `backend/tests/test_city_twin.py`. Registration in `api/v1/__init__.py` and `main.py` is done by the lead (export `router` and `ws_router` from city_twin.py).
All endpoints accept an OPTIONAL bearer token (`get_optional_user`). Anonymous = public map-safe view.
Privacy: anonymous and non-owner citizens get coordinates rounded to 3 dp and NO reporter data; owners and staff get exact coordinates. Never include phone/email/name/internal notes/AI confidence-for-citizens. Features never include `original_description` (only `summary`, i.e. public summary).
* `GET /city-twin/summary` → `{demo_mode:bool, data_sources:{complaints:"civiclens_database", vehicles:"simulated|gps_device|manual", bins:"simulated|worker|sensor"}, counts:{complaints_active,complaints_resolved,critical,high,vehicles_active,bins_total,bins_overflow_risk}, role_view:"public|citizen|officer|worker|supervisor|admin", map_default:{center:[lng,lat],zoom,pitch:55,bearing:-15}, simulation_label:"DEMO MODE — Vehicle locations and bin readings are simulated.", last_updated}`.
* `GET /city-twin/complaints` query: `severity, category, status, department, date_from, date_to, mine(true), include_resolved(false), limit(<=1000)` → GeoJSON `FeatureCollection` (coordinates `[lng,lat]`). Feature properties (map-safe only): `ticket_id` (= public ticket number, e.g. CL-2026-00142), `category, category_name, subcategory, severity, status, priority_score, public_summary, department_code, department_name, locality, created_at, updated_at, resolved_at, supporting_count, is_mine, is_demo, requires_review(staff only)`. Sorted by priority desc. Staff scoping uses the same visibility rules as `/officer/queue` (officer → own department; worker → assigned; supervisor/admin all) ONLY for staff-only fields; the geographic list for the public map is all non-rejected complaints (public-safe), so every role sees the same city.
* `GET /city-twin/complaints/{ticket_id}` → citizen-safe detail for the side panel: the properties above plus `original_language, severity_reason, timeline:[{to_status,note,created_at}] (public rows only), images:[{id,kind}] (report/before/after; images are fetched with the authenticated `GET /images/{id}`, so for anonymous viewers return an empty list and `images_require_login:true`), before_after:{before_image_id|null, after_image_id|null, verified:bool, verified_at|null} (only populated when status is resolved), department_name, ward/corporation fields (null when not resolved), "view_full_report_path": "/app/complaints/{ticket}" or "/staff/tickets/{ticket}" by role`. Staff additionally get `ai_confidence, review_reasons, routing_note, sla_due_at, assigned_worker_name`. 404 for unknown/rejected.
* `GET /city-twin/vehicles` → `{simulated, source_label, items:[{vehicle_id, vehicle_code, status:"moving|collecting|idle|delayed|completed|offline", longitude, latitude, heading_degrees, route_progress, route_id, route_code, route_name, next_stop, data_source:"simulated|gps_device|manual", recorded_at, stale:bool, stale_seconds}]}` from the latest `vehicle_locations` per vehicle (the CleanRoute simulator writes them). `status` derives from `garbage_vehicles.status`/speed (speed ~0 near a bin → collecting). `stale` when `recorded_at` older than 30 s AND source not simulated-autostart off; if the simulator is not running and data is simulated, mark `stale:true` too (never pretend it is moving). Staff only extras: `driver_label`. **Never** return driver details to anonymous/citizens. `speed_kmh` and ETA only for staff and labelled `demo_estimate:true`.
* `GET /city-twin/vehicles/{vehicle_id}` (id or code) → vehicle + route summary.
* `GET /city-twin/routes` → GeoJSON `FeatureCollection` of `LineString`s `[lng,lat]` built from `garbage_routes.waypoints` (which are `[lat,lng]` — swap!) with properties `route_id, route_code, name, schedule_window, is_simulated, length_m, vehicle_codes`.
* `GET /city-twin/bins` → `{simulated, source_label, thresholds, items:[{bin_id, bin_code, public_label, longitude, latitude, fill_percentage, status:"normal|filling_up|collection_recommended|overflow_risk", data_source, last_collected_at, last_reading_at, predicted_full_at|null, route_id}]}` using latest `bin_readings`, `collection_events`, thresholds from `app_settings.bin_thresholds` (same function the garbage API uses: 0–50 normal, 51–80 filling_up, 81–95 collection_recommended, 96–100 overflow_risk).
* `GET /city-twin/bins/{bin_id}` (id or code) → bin + `history:[{event_type:"collected", vehicle_code, recorded_at, data_source}]` last 10.
* `GET /city-twin/layers/config` → `{layers:[{id:"complaints",label,default:true,roles:"all"},{id:"resolved",default:false},{id:"vehicles",default:true},{id:"routes",default:true},{id:"bins",default:true},{id:"buildings",default:true}], filters:{severities,categories(from DB),statuses,departments}, legend:[…]}`.
* Officer/admin actions REUSE existing endpoints (no duplicates): collection events `POST /garbage/collections`, bin readings `POST /garbage/bins/{id}/reading`, simulation `POST /demo/garbage/start|stop`, status/verify `PATCH /complaints/{id}/status`, `POST /complaints/{id}/verify-resolution`. Do NOT re-implement them. (The UI calls those.)
* WebSocket `/ws/v1/city-twin/live` (`ws_router`): public read-only, optional `?ticket=` not needed. On connect send `{"type":"snapshot","ts","demo_mode","vehicles":[…],"bins":[…],"complaints_version":<int>}`. A background per-connection loop every 2 s queries the DB and sends ONLY deltas: `{"type":"vehicle.position.updated","data":{…vehicle item…}}` for vehicles whose latest `recorded_at` changed, `{"type":"bin.fill.updated","data":{…bin item…}}` for bins whose latest reading changed, `{"type":"complaint.status.updated","data":{ticket_id,status,severity,category,longitude,latitude(public 3dp),public_summary,updated_at}}` for complaints whose `updated_at` > last check (include newly created ones as `complaint.created`). Also respond to client text `ping` with `pong`. Handle disconnects. Data comes from the DB tables only (decoupled from the simulator internals; if the CleanRoute simulator writes `VehicleLocation`/`BinReading`, the feed moves). Close gracefully on server shutdown.
* Tests (conftest fixtures; create rows directly with models): public features contain no PII keys (assert key set), anonymous gets rounded coords, owner gets exact, staff extras, filters (severity/category/status/mine/include_resolved), resolved hidden by default, routes swap lat/lng correctly, bins status thresholds, vehicle stale flag, WS snapshot + a delta after modifying a complaint's status in the DB (use `TestClient.websocket_connect`).

## Frontend (owner: CITY-TWIN-FE)
Route `/city-in-motion` (public; already wired in `App.jsx` to `src/pages/CityInMotion.jsx`, which must default-export the page). Files: `src/pages/CityInMotion.jsx` (thin wrapper) and everything under `src/features/city-in-motion/` (components/, hooks/, services/, utils/ exactly as the 3D spec section 13 lists), plus `public/models/README.md`, `docs/assets/ASSET_CREDITS.md`. The page renders OUTSIDE the citizen/staff layouts (full-viewport) with its own slim top bar: CivicLens logo (link home), view switch `Civic issues | CleanRoute`, 2D/3D toggle, role-aware links (Dashboard → `/app` or `/staff`, Sign in when anonymous), `LanguageSwitcher` from `src/components/LanguageSwitcher.jsx` if it exists (import defensively? NO — it will exist; the CITIZEN-CORE agent writes it).
See `docs/SPECIFICATION_3D_CITY_TWIN.md` sections 4–9, 13, 19, 20 for behaviour. Must-haves:
* One MapLibre map (created once in an effect, cleaned up on unmount; `ResizeObserver` → `map.resize()`), pitch 55 / bearing −15 / zoom 12 / centre `[77.5946, 12.9716]` (from `GET /city-twin/summary.map_default`), style `VITE_CITY_MAP_STYLE_URL` default OpenFreeMap liberty, building extrusions kept visible from zoom 14 with the style's own `building-3d` layer retuned (muted warm grey `#D8DAD3`, opacity .88) — if that layer id is absent add a `fill-extrusion` on source `openmaptiles` source-layer `building`; restyle the basemap toward Civic Minimalism where cheap (paper-toned land, no neon) by `setPaintProperty` on layers that exist; visible attribution; navigation + scale controls; reset-camera and 2D/3D (pitch 0 vs 55) buttons; fullscreen; locality search using the existing `GET /locations/search` when signed in (anonymous: hide search, say why).
* Complaint layer from `GET /city-twin/complaints` as a GeoJSON source with clustering (cluster circles with counts, forest/civic colours), unclustered circle layer + icon-like symbol (halo ring, severity colour, critical gets a white "!" glyph via a symbol layer with `text-field`, do NOT rely on colour alone: also vary radius and add ring pattern for status "under review" = hollow ring), resolved = muted green with check glyph (layer toggle, off by default), filters (severity, category, status, department, date range, "Show only my reports" when signed in) applied via `map.setFilter` / refetch — never rebuilding the map. Marker click → right-hand details panel (not popups): `GET /city-twin/complaints/{ticket}`; shows public summary, status, severity + reason, location, timeline, linked reports, department, `View full report` link, before/after images via `AuthImage` when signed in (else "Sign in to view photos"), staff see the extra fields + deep link to `/staff/tickets/{ticket}`. Hover cursor + keyboard-accessible list view alternative (a "List" tab listing the same filtered features, sorted by priority, selecting one flies to it) — required for accessibility and mobile.
* CleanRoute layer: routes (`GET /city-twin/routes`, line layer: completed segment muted green, remaining neutral dark — compute split client-side from `route_progress` with simple along-line math in `utils/routeMath.js`, next stop highlighted), bins (`GET /city-twin/bins`) as circle layer coloured by status with fill % label at zoom ≥ 14 and small Three.js bin prisms optional, vehicles as a MapLibre **custom 3D layer** with Three.js (`type:'custom', renderingMode:'3d'`, `onAdd(map, gl)`, `render(gl, matrix)`; use `THREE.WebGLRenderer({canvas: map.getCanvas(), context: gl})`, `renderer.autoClear=false`, `renderer.resetState()` each frame, `MercatorCoordinate.fromLngLat(...).meterInMercatorCoordinateUnits()` for scale; model orientation convention documented once in `utils/mapConfig.js` (`MODEL_FORWARD = +Y` etc.), heading from server `heading_degrees`; smooth client-side interpolation (lerp ~ over the update interval, `map.triggerRepaint()` in rAF while any vehicle is animating); instanced/reused geometry and materials; procedural truck builder in `components/truckModel.js` (+ optional GLB loader when file exists); labels (vehicle code) as HTML markers or a symbol layer). Fallback: if WebGL/custom layer fails → 2D MapLibre circle/symbol vehicle layer, and if MapLibre itself fails → clear error with Retry and a 2D Leaflet fallback (react-leaflet is installed; reuse `lib/leaflet.js`) showing the same API data.
* Live data: `hooks/useGarbageLiveFeed.js` connects to `${WS_BASE}/ws/v1/city-twin/live` (snapshot + deltas as in the backend contract), reconnects with backoff, shows `Live updates paused` when disconnected, falls back to REST polling every 5 s, marks stale vehicles with `Location may be outdated` (never animates stale/offline vehicles), applies `complaint.status.updated` to the complaint source (marker restyles with a 300–500 ms scale/fade; no confetti) and refreshes the open panel if it is that ticket. All data labelled: persistent banner `DEMO MODE — Vehicle locations and bin readings are simulated.` (use the summary's `simulation_label`; show a `Simulated GPS` badge on vehicles and `Simulated sensor` on bins — mapping from `data_source`).
* Vehicle panel: code, route, status chip, route progress bar, next stop, last update time, data-source badge, "Demo ETA" only when provided (staff) and labelled; no driver data for non-staff. Bin panel: code, label, fill %, status, last collection, data-source badge, predicted full time labelled "estimate". Staff-only quick actions: "Record collection" (`POST /garbage/collections`), "Record reading" (`POST /garbage/bins/{id}/reading`), admin Start/Stop simulation (`POST /demo/garbage/start|stop`); after success, refetch. Complaint staff actions deep-link to the ticket screen (do not duplicate the officer workflow).
* Left rail: layer toggles + filters + legend (`MapLegend`, severity icons + labels), collapsible on tablet; right panel → bottom sheet on mobile; mobile defaults to 2D (pitch 0) with a 3D toggle; lazy-load three/maplibre via dynamic `import()` only when the page opens (route is already lazy; also lazy-load three inside the vehicle layer module). `prefers-reduced-motion` respected (no interpolation easing beyond linear, no marker transitions).
* Design: Civic Minimalism per `index.css` tokens: paper rails, white panels, 1px borders, 10 px radius, NO gradients/neon/glow, no emoji; severity colours: critical `#B94A48` with "!" glyph, high `#C2603A`, medium `#2F5F8F`, low `#7B8A93`, resolved `#397A56` with check; bins use forest/saffron/amber/red; use civic blue for route lines.
* Verification: `npx vite build` must pass. Do not start servers.
